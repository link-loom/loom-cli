## Iteration notes

Second run: a new agent with the CLI of iteration 1's fixes. It passed every gate with no hand edits, and used the
new pieces (schema migration, dry runs, sidebar groups and sections, links). What it could not do, and what changed:

- A carried page used a service whose file was discarded: the import was dropped with only a note, and the tests
  crashed on an undefined name. `apply` now refuses it and says which file to carry or which import is gone.
- Texts in ternaries and `cond && "…"`, and in `confirmButtonText`/`cancelButtonText`-style keys and props, were
  not extracted: they are now. Texts the agent added by hand to the decisions (no text at that offset) were ignored
  in silence: `apply` now lists them.
- An error without `--json` printed its message but not its problems (which file collides): the human output now
  lists them.
- The agent turned Omnisearch off for an entity titled by `display_name`, believing it needed `name`: the schema
  of `omnisearch` now says any first field works.

- In the browser walk of the migrated app, Omnisearch spoke English in a Spanish app ("Search (⌘K)", "Ask AI anything
  or search…", its headings and footer): the react-sdk's OmniSearch takes `labels` now (English by default, additive)
  and the generated navbar passes `copy.omnisearch` in en and es.

Not carried, by design for now: role gating of sidebar rows, the navbar "+" entries and Omnisearch categories of
legacy services, and sentences built from template pieces (they stay in English and the agent listed them).
